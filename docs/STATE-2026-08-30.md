# Verza TV — state at 2026-08-30

Written at the end of a long session so the next one starts from fact rather
than from memory. Everything here was measured, not assumed. Where something is
unverified it says so, because the most expensive mistakes in this project have
all been confident claims that turned out to be stale.

## Where things stand

`main` is at the commit that added the scrubber and the self-healing player.
The working tree is clean, local and `origin/main` are identical, and the live
alias serves it. 17 commits landed in this session.

## The invariants — break these and the product breaks

Each one exists because a real defect reached production. Each is enforced by a
check in `scripts/test-feed-integrity.mjs`, and each of those checks has been
negative-controlled: the fix was removed, the gate was watched to fail, the fix
was restored.

**The rail is bounded by entitlement.** An unentitled viewer gets
`freeEpisodes + 1` slides and no more. Before this, the feed built a scroller as
tall as the whole series — 60 viewports for someone entitled to five — and the
counter could walk to the end over black locked slides.

**The scrollport holds previous, current and next, and no spacers.** The spacers
WERE the runway: bounding the mounted components while leaving them in place
bounded nothing a fling could feel. The recycle re-centres in a
`useLayoutEffect` with `behavior: "instant"`.

**No corrective clamp.** Measuring an overshoot and putting the scrollport back
was tried and deleted. iOS does not reliably permit undoing momentum, a
correction that lands is a visible jump, and it had a hole for the second of two
fast flicks.

**Audio is never gated on a composited frame.** The unmute lives inside the
`play()` promise. WebKit allows an unmute without a fresh gesture only inside a
one-second grace window armed by the previous `ended`, and
`requestVideoFrameCallback` overran it.

**Every `<video>` claims the WebKit gesture.** `play()` called during a user
gesture removes that element's audio restrictions for its whole lifetime.
`lib/instant-player.ts` claims it synchronously in the poster tap; each touch on
the feed claims it for every mounted slide via `dataset.verzaGestureClaimed`.
This is the difference between sound and silence from the second episode on.

**No global `scroll-behavior: smooth`.** It caused three separate defects, in
`CategoryTabs`, `BrowsePage` and `EpisodeFeed`, none of which looked like a CSS
problem from the symptom. Smooth scrolling is a per-interaction decision.

**`touch-action: pan-y` on the seek strip, never `none`.** `none` claims
vertical gestures too, which stops the feed scrolling across the bottom of the
screen whenever the action rail is up.

**Failure states heal before they complain.** The player escalates recovery
cheapest-first and only shows an error after a real, attempted, failed one. The
error screen is not decoration and must not be deleted: an indefinite black
frame with no explanation is what the app did before it existed.

**Playable plays, unplayable explains.** `posterHref()` owns that decision. All
91 live rows resolve to their player; the 5 coming-soon rows to their show page,
because `/series/<slug>/1` is a real 404 for a row with `episodeCount 0`.

**Continue Watching never reorders a grid.** It is the last row of a section and
lists only that section's titles, with membership derived from the same list the
grid renders. Watch state is not an input to the ordering memo, and the gate
asserts it cannot become one.

**SEO surface: 91 show pages, 2,214 episode pages.** No URL may change.

## How to work on this safely

Run `npm run test:feed-integrity` before and after anything touching the player,
routing or the browse page. It walks all 4,913 episodes offline and every check
names the defect it prevents.

Four rules, each learned by getting it wrong here:

1. **Verify the effect, never the assignment.** A rendition cap was written to
   `config` and did nothing, because the real switch is a setter that starts a
   controller.
2. **Measure, do not reason.** Three fixes shipped from pure reasoning failed on
   the founder's phone. The ones that worked were measured in a browser or on a
   simulator.
3. **Negative-control every test.** Five vacuous checks were found this session,
   every one by running the control rather than by reading the test. One whole
   section sat below the reporter's `process.exit` and could not fail at all.
4. **Re-check inherited facts.** Roughly a quarter of asserted facts in this
   project have been wrong or stale, including several previously reported as
   shipped.

## Open, and owner-blocked

These need a human and are documented in `docs/audit/fix-plan.md`:

- **The active Supabase project's host does not resolve. Corrected reading —
  this is worse than a misconfiguration.** The client bundle carries
  `mmvbmrrwgludfmfalfcm.supabase.co`, and that is the CORRECT project: the July
  2026 migration moved off `jejispfvlkwastzvwtwu` deliberately, and .env.local
  and the Vercel production env were both rewired to it at the time. So nothing
  is pointing at the wrong place.

  The problem is that the correct host no longer answers. Confirmed against two
  independent public resolvers (1.1.1.1 and 8.8.8.8): no A record, and HTTPS to
  `/auth/v1/health` and `/rest/v1/` both return 000, no connection. It is not a
  local DNS or network problem — supabase.com itself resolves fine from the same
  machine, and the OLD project `jejispfvlkwastzvwtwu` still resolves. A project
  that has been paused normally still resolves and serves an error; one that has
  stopped resolving entirely reads as deleted or torn down.

  So the fix is NOT an environment variable. It is: find out what happened to
  that project, and restore it or stand up a replacement and re-point the env.
  The July migration notes in memory list everything that has to exist —
  migrations 001-008, the `handle_new_user` trigger on `auth.users`, and the
  API-role GRANTS that the raw SQL API does not apply automatically and whose
  absence returns 403/401 with code 42501 across the whole app.

  Anonymous routes still answer 200/401 because they short-circuit before
  touching Supabase, which is exactly why this is invisible from the outside
  until somebody tries to sign in.
- `?platform=ios` on any URL permanently disables every purchase surface in that
  browser, with no reset path.
- Source master video files for paid episodes are publicly downloadable.
- The rate limiter does not bind in production: the bucket is an in-process Map
  and each serverless instance gets a fresh one.
- The security gates pass with paid-playback authorization deleted.
- `/sign-in?error=a&error=b` returns 500 — the repeated-parameter bug fixed in
  `/search` is still present on the auth pages.
- Mux audio tracks are `LANGUAGE="und"`; fixing it needs re-ingestion with
  credentials this repo deliberately does not hold.

## What no agent could verify

Nobody has ever completed a purchase on this platform, so checkout is unverified
by definition rather than by omission. No agent can hold an iPhone: finger
swipes, tap reachability, safe areas and real momentum remain unproven, and
every browser measurement this session ran in a backgrounded tab, which suspends
video decode and both animation-frame APIs. `docs/audit/cannot-verify.md` has
the full list.
